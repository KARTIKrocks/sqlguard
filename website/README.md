# sqlguard documentation site

The source for <https://kartikrocks.github.io/sqlguard/>, built with
[Docusaurus](https://docusaurus.io/).

It lives on `main` alongside the code on purpose: a PR that changes documented
behaviour should change the docs in the same review. Docs on a separate branch
drift from the code they describe.

## Local development

```bash
npm ci
npm start        # http://localhost:3000/sqlguard/
```

`npm start` builds only the unreleased docs plus the newest version so startup
stays fast as versions accumulate. Use `npm run start:all` to preview every
live version.

## Before pushing

```bash
npm run check    # lint + typecheck + build
```

Individually:

| Command | Does |
| --- | --- |
| `npm run lint` | Biome lint + format check |
| `npm run lint:fix` | Biome autofix |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run build` | full production build, all live versions |
| `npm run build:fast` | narrowed build — what CI runs on PRs |

Markdown is linted separately, repo-wide, with `make lint-docs` from the
repository root (Biome has no Markdown support). Config and rationale live in
`../.markdownlint-cli2.jsonc`.

## Editing docs

Pages are Markdown in `docs/`, roughly one file per concept or package. To add
one:

1. Create `docs/<id>.md` with `id`, `title`, and `description` frontmatter.
2. Add the id to `sidebars.ts` under the right category.

The sidebar is explicit rather than autogenerated, so ordering is deliberate and
a new file cannot silently rearrange the nav.

**Documenting a new API?** Mark the version that introduced it — `_0.3+_` in a
table cell, `_Added in 0.3._` opening a paragraph, `// 0.3+` in a code block.
Most releases are additive and get no snapshot of their own, so this marker is
the only thing telling a reader on an older version what they need to upgrade
to.

**Every option and function name must match an exported identifier exactly.**
A wrong name here is a support burden, not a typo — check against the source
(or pkg.go.dev) before writing it.

**`docs/` is the unreleased version.** It tracks `main` and is served at
`/docs/next/`. The released docs readers land on live in
`versioned_docs/version-<minor>/`. See [VERSIONING.md](VERSIONING.md) before
cutting a release or fixing docs for an already-released version.

## Blog

The blog plugin is wired up but has no posts, so there is no Blog link in the
navbar or footer. When the first post lands under `blog/`, add the links back
in `docusaurus.config.ts` in the same change. Authors are declared in
`blog/authors.yml`; posts must use `{/* truncate */}` as the excerpt marker.

## Deployment

Pushing to `main` deploys via `.github/workflows/docs.yml`. There is nothing to
run by hand — do not commit built output to a branch.

## Search

Algolia DocSearch is stubbed out in `docusaurus.config.ts`. Apply at
<https://docsearch.algolia.com/apply/> and uncomment the block once approved.
